## Overview

This is a federated learning project built on NVIDIA FLARE (NVFlare) that enables distributed machine learning across multiple client nodes. The system uses Ansible for infrastructure management and Docker for containerized deployments. The architecture supports training PyTorch models (MNIST, CIFAR-10, ResNet) across multiple clients with different data distribution strategies.

**For deployment instructions, see [DEPLOYMENT.md](DEPLOYMENT.md)**

## Architecture

### Three-Tier Structure

1. **Infrastructure Layer (Ansible)**: Manages deployment, provisioning, and configuration of NVFlare server and clients
2. **NVFlare Layer**: Provides the federated learning framework with server-client communication
3. **Application Layer (Jobs)**: Contains specific FL training jobs with model definitions and training scripts

### Key Components

- **Server Node**: Coordinates federated learning rounds, aggregates models (located at `172.19.1.7`)
- **Client Nodes**: Train models locally on distributed data (k3s-client-06, 08, 09, 17, 18)
- **Admin Interface**: Manages jobs and monitors training (`admin@nvidia.com`)

### Workspace Organization

- `workspace/example_project/prod_00/`: Runtime workspace generated by NVFlare provisioning
  - Each client/server has its own directory with startup kits and configuration
  - UUIDs represent individual job runs
  - Contains generated `app_*/` directories with model code and configs

## Common Commands

### Infrastructure Management

```bash
# Test connectivity to all nodes
ansible-playbook -i ansible/inventory.ini ansible/playbooks/ping_all_nodes.yml

# Deploy NVFlare with Docker across all nodes
ansible-playbook -i ansible/inventory.ini ansible/playbooks/deploy_docker_nvflare.yml

# Install packages on clients
ansible-playbook -i ansible/inventory.ini ansible/playbooks/install_python_package.yml

# Clone repository to clients
ansible-playbook -i ansible/inventory.ini ansible/playbooks/clone_repo.yml

# Run arbitrary script on nodes
ansible-playbook -i ansible/inventory.ini ansible/playbooks/run_script.yml
```

### NVFlare Operations

```bash
# Provision a new NVFlare project (creates workspace with certs/configs)
nvflare provision -p project.yml -w workspace/example_project

# Start server container
cd workspace/example_project/prod_00/mylocalhost/startup/
./docker.sh -d

# Start client container
cd workspace/example_project/prod_00/k3s-client-XX/startup/
./docker.sh -d
```

### Job Management

```bash
# Generate a federated learning job configuration
cd jobs/pt_resnet
python fedavg_script_runner_pt.py -p ../../project.yml

# The generated job will be in jobs/pt_resnet/job_config/
# Deploy via NVFlare admin console or API
```

### Data Distribution

```bash
# Split and distribute HIGGS dataset
python scripts/distribute_splits.py \
  --data_path /path/to/HIGGS.csv \
  --split_method square \
  --inventory ansible/inventory.ini \
  --remote_dest /tmp/nvflare/data_splits

# Split methods: uniform, linear, square, exponential
# - uniform: equal data per client
# - linear: linearly increasing data (1 to M)
# - square: quadratically increasing data (1² to M²)
# - exponential: exponentially increasing data (exp(1) to exp(M))
```

### Docker Operations

```bash
# View running containers
docker ps

# View logs
docker logs nvflare-pt-docker

# Stop containers
docker stop nvflare-pt-docker

# Remove containers
docker rm nvflare-pt-docker
```

## Data Splitting Strategies

The project includes utilities for non-IID data distribution to simulate heterogeneous federated learning:

- **Uniform**: All clients receive equal amounts of data (IID baseline)
- **Linear**: Data scales linearly with client ID (mild heterogeneity)
- **Square**: Data scales quadratically (moderate heterogeneity)
- **Exponential**: Data scales exponentially (extreme heterogeneity)

Use `notebooks/utils/data_utils.py:split_and_distribute()` for tensor-based datasets or `scripts/distribute_splits.py` for file-based datasets.

## Job Configuration

Jobs follow NVFlare's structure under `jobs/`:

- `fedavg_script_runner_pt.py`: Job generator that reads `project.yml` to create client-specific configs
- `src/`: Model definitions (e.g., `resnet_18.py`, `mnist_cnn.py`) and training scripts (`pt_mnist_fl.py`)
- `job_config/`: Generated configuration with per-client app directories
  - `app_server/`: Server configuration and aggregation logic
  - `app_<client_name>/`: Client-specific executors and training scripts
  - Each uses `PTInProcessClientAPIExecutor` for PyTorch in-process execution

## Important Configuration Files

- `project.yml`: Defines all participants (server, clients, admin) and NVFlare builder configuration
- `ansible/inventory.ini`: Ansible inventory with server/client IP addresses and deployment variables
- `jobs/pt_resnet/requirements.txt`: Python dependencies for federated jobs (nvflare, torch, torchvision)

## Development Workflow

1. **Prepare Data**: Use notebooks to download/prepare datasets, then distribute using `data_utils.py`
2. **Configure Participants**: Update `project.yml` with server IP and client names
3. **Provision Workspace**: Run `nvflare provision` to generate certs and configs
4. **Deploy Infrastructure**: Use Ansible playbooks to deploy Docker containers
5. **Create Job**: Run job generator script (e.g., `fedavg_script_runner_pt.py`) to create job configs
6. **Submit Job**: Use NVFlare admin console to submit job to server
7. **Monitor Training**: Track progress through logs and admin interface
8. **Collect Results**: Results stored in workspace under job UUID directories

## Network Configuration

- Server listens on:
  - Fed learn port: 8002
  - Admin port: 8003
- All clients configured with `--add-host=mylocalhost:<server_ip>` in Docker to resolve server hostname
- Static IP assignments in `172.19.1.x` subnet

## Key Python Modules

- `notebooks/utils/data_utils.py`: Dataset splitting and Ansible-based distribution
- `jobs/pt_resnet/src/pt_mnist_fl.py`: Example federated training script using NVFlare Client API
- `jobs/pt_resnet/src/resnet_18.py`: ResNet18 model wrapper for NVFlare Job API compatibility
- `scripts/distribute_splits.py`: Automated data splitting and distribution utility

## Docker Image

Base image: `nvcr.io/nvidia/pytorch:25.06-py3`
Custom image: Built from `ansible/Dockerfile` with NVFlare ~2.6.1rc and cloned examples

## Notes

- The workspace directory is auto-generated and should not be edited manually
- Job configurations use UUIDs to identify specific runs
- Client training scripts must use NVFlare's Client API (`flare.init()`, `flare.receive()`, `flare.send()`)
- The project supports both script-based execution (`ScriptRunner`) and model learner approaches
- Data is NOT automatically distributed - must be manually split and copied to clients before job execution
